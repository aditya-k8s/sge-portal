# Free test deployment — a shareable HTTPS URL

Gets the portal onto a public HTTPS address you can send to testers, at no
cost, with a SQL database whose data persists.

| Piece | Service | Free allowance |
|---|---|---|
| Database | **Aiven MySQL** | Always free, 1 GB storage, 1 GB RAM, automated backups, no card |
| Web app | **Render** | Free web service, 512 MB RAM, HTTPS on `*.onrender.com`, no card |

**Why not Render's own free database:** Render's free PostgreSQL expires 30
days after creation and is then deleted. Aiven's MySQL free tier does not
expire, and it keeps the app on MySQL, so no code, settings or migration
changes are needed.

HTTPS matters beyond security here: **Chrome will not offer to install the app
on Android without it.** Both services provide it automatically.

---

## Step 1 — Create the free MySQL database

1. Sign up at [aiven.io](https://aiven.io/free-mysql-database). No card required.
2. **Create service → MySQL**, choose the **Free** plan, and pick the region
   closest to your testers.
3. Wait until the service shows **Running** (a few minutes).
4. From the service **Overview**, note the connection details:

   | Field | Typical Aiven value |
   |---|---|
   | Host | `mysql-xxxxx-yyyyy.<region>.aivencloud.com` |
   | Port | a 5-digit port, not 3306 |
   | User | `avnadmin` |
   | Password | shown on the overview page |
   | Database | `defaultdb` |

5. Download the **CA certificate** (`ca.pem`) from the same page. Aiven
   requires TLS.

Treat the password as a credential: do not paste it into chat, a commit, or a
ticket. It belongs in `.env` locally and in Render's environment variables.

## Step 2 — Create the schema and the first admin user

Render's free tier has **no shell**, so you cannot run `migrate`,
`seed_data` or `createsuperuser` on the server. Do it from your machine
instead — the Aiven database is reachable over the internet, so this works
and gives you full control. It also verifies the schema against real MySQL
before anything is deployed.

Point your local `.env` at Aiven temporarily:

```env
DB_ENGINE=mysql
DB_NAME=defaultdb
DB_USER=avnadmin
DB_PASSWORD=<the Aiven password>
DB_HOST=<the Aiven host>
DB_PORT=<the Aiven port>
DB_SSL_CA=C:/path/to/ca.pem
```

Then:

```bash
python manage.py migrate
python manage.py createsuperuser        # your real admin account
python manage.py seed_data              # optional: demo machines and projects
```

Confirm it worked:

```bash
python manage.py dbshell
SHOW TABLES;
SHOW INDEX FROM projects_project;
```

Keep these settings in `.env` if you want to run locally against the shared
database, or switch back to your local MySQL afterwards — Render has its own
copy of these values.

## Step 3 — Deploy the web app

1. Push the repository to GitHub (this project already has an `origin`):

   ```bash
   git add -A && git commit -m "Add free-tier deployment configuration"
   git push origin prod
   ```

2. Sign up at [render.com](https://render.com) and connect your GitHub account.
3. **New → Blueprint**, choose this repository. Render reads `render.yaml` and
   proposes a service named `sge-portal`.
4. Render prompts for the values marked `sync: false`. Fill in:

   ```
   DB_ENGINE     mysql
   DB_NAME       defaultdb
   DB_USER       avnadmin
   DB_PASSWORD   <the Aiven password>
   DB_HOST       <the Aiven host>
   DB_PORT       <the Aiven port>
   DB_SSL_CA     /etc/secrets/ca.pem
   SITE_URL      https://sge-portal.onrender.com
   ```

   `SECRET_KEY` is generated by Render automatically. You do not need to set
   `ALLOWED_HOSTS` to the Render hostname — `config/settings.py` reads
   `RENDER_EXTERNAL_HOSTNAME` and trusts it, including for CSRF.

5. Add the CA certificate: service → **Environment → Secret Files → Add**,
   filename `ca.pem`, and paste the contents of the Aiven `ca.pem`. Render
   places it at `/etc/secrets/ca.pem`, which is what `DB_SSL_CA` points at.

   If secret files prove awkward, remove `DB_SSL_CA` and set `DB_SSL=true`
   instead. That still encrypts the connection but does not verify the
   server's certificate, so prefer the CA file.

6. **Create**. The build installs dependencies, runs `collectstatic` and
   applies migrations. First build takes a few minutes.

Your URL is `https://sge-portal.onrender.com` (Render shows the exact one).

### Optional: email

Leave the email variables unset and sending simply fails and is logged — fine
if testers are accounts you create yourself. If testers must **register
themselves**, they need the OTP email, so either:

- set `EMAIL_HOST_USER` and `EMAIL_HOST_PASSWORD` to a Gmail address and a
  16-character [App Password](https://myaccount.google.com/apppasswords), or
- set `EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend` and read
  the codes out of the Render logs yourself.

## Step 4 — Test the installable app

**Android Chrome:** open the `https://…onrender.com` URL, then tap
**Install App** in the page, or **⋮ → Add to Home screen → Install**. It
launches full screen with no browser chrome.

**Desktop Chrome:** open the URL and use the install icon in the address bar,
or **⋮ → Cast, save and share → Install page as app**.

Diagnose any problem under **F12 → Application → Manifest**.

## What to expect from the free tier

These are the limits, not defects:

| Behaviour | Why | Matters because |
|---|---|---|
| **First request after 15 minutes idle takes ~50 seconds** | Render spins down idle free instances | Warn your testers, or they will think it is broken. Open the URL yourself just before sharing it. |
| **Uploaded drawings and invoices disappear on redeploy** | The instance disk is ephemeral | Database records survive on Aiven; the files themselves do not. Fine for testing the workflow, not for real documents. |
| 1 GB database | Aiven free plan | Ample for testing. |
| 512 MB RAM, 0.1 CPU | Render free plan | Runs two Gunicorn workers; PDF generation is the heaviest operation. |
| Single node, no HA | Both free plans | Expected. |

Uploads surviving redeploys needs object storage (S3, Cloudflare R2,
Cloudinary) and a storage backend — worth doing before this holds anything
real, and out of scope for a test deployment.

## Redeploying

```bash
git push origin prod
```

Render rebuilds automatically, which reruns `collectstatic` and `migrate`.

## Alternative: an instant URL with no signup

To show someone the app running on your own machine for an hour, with no
account anywhere:

```bash
# install cloudflared, then:
python manage.py runserver 0.0.0.0:8000
cloudflared tunnel --url http://localhost:8000
```

That prints a `https://<random>.trycloudflare.com` URL. Add the hostname to
`ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS` in `.env` and restart the server.
Everything works, including uploads and email, because it is your machine —
but the URL dies when you stop the command and is different next time.

## Before this becomes more than a test site

- Rotate the credentials that were previously committed to git (see the
  security note in `README.md`).
- Change the seeded demo passwords, or skip `seed_data` entirely and create
  only real accounts.
- Move uploaded files to object storage.
- Take Render off the free plan to remove the cold start, or move to a small
  VPS with Nginx and Gunicorn as described in `README.md`.
